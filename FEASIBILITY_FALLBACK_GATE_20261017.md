# Feasibility Fallback Gate — 17.10.2026

**Решение: GO — 10/10 обязательных проверок.** Это техническая готовность исправления к рассмотрению, не разрешение на staging, commit, запуск или развёртывание.

Исправлена подтверждённая ложная пустота обычных Balanced/Lexicographic: Beam выполняется без изменения ранжирования и ширины, а после отсутствия проверенных основных результатов запускается отдельный ограниченный поиск допустимости. Резерв не максимизирует приоритеты и не минимизирует цену.

## Порядок работы и корректность

1. Основной поиск и его целевая функция выполняются как прежде.
2. У выбранных реальных лотов проверяются текущая запись EU/RU нужного региона, цена, тип, качество, заточка, процент, random-параметр, известные бонусы и `end_time` с UTC.
3. Если выбранные верхние результаты отвергнуты, сначала проверяются остальные уже найденные основные результаты. Если остаётся хотя бы один допустимый основной результат, **MILP не запускается**.
4. Только после пустого проверенного основного результата обрабатываются сохранённые подготовленные профили. Используются реальные текущие кандидаты, без генерации новых лотов и без переноса старых индексов.
5. Модель требует ровно число слотов контейнера, соблюдение бюджета артефактов, ограничений min/max, физических групп и запрета повторов типов при соответствующем флаге. Фиксированная броня/контейнер входят в бонусы. Для положительной суммы четырёх накоплений учитывается внутренняя защита, мороз отдельно.
6. Нулевая целевая функция ищет только допустимое заполнение. Любые целочисленные индексы заново проверяются через `_process_combo()` и `_final_valid()`, включая повторную проверку лотов после solver. Время истечения или изменение записи за время расчёта отклоняет результат.

Гарантированная носимость, резерв с `conservative=True`, ограничения на производный `stopping_protection` и внутренние неподдерживаемые поля дают **UNKNOWN**, без ослабления условий. Поддержка этих случаев основным поиском не удалялась. Отсутствующие/неизвестные проценты и неизвестные уже разблокированные бонусы не заменяются оценочными. На заточке +1…+4 отсутствие бонусов корректно, если первый unlock находится на +5.

У собственных артефактов сохраняются заявленные в запросе физические экземпляры и бесплатная цена; реальное владение внешним инвентарём не аутентифицируется этой проверкой. Анонимные программные кандидаты не используются резервом как покупаемые лоты. Для существующего программного основного поиска сохранён прежний контракт таких фикстур, с `availability_verified=false`.

## Лимиты

Лимиты отдельны от `min_budget_timeout`:

| Ограничение | Значение |
| --- | ---: |
| Общий бюджет резервного этапа MILP | 5 с |
| Лимит одной модели, дополнительно ограниченный оставшимся бюджетом | 3 с |
| Кандидатов одной модели | 5000 |
| Сохранённых профилей | 16 |
| Кандидатов суммарно в сохранённых профилях | 20 000 |
| Пользовательских min/max | 256 |
| Строк / ненулевых коэффициентов | 10 000 / 100 000 |
| Узлов одной модели | 10 000 |

В модель передаётся `min(оставшееся время, 3 с)`; при малом остатке увеличение до полного лимита запрещено и проверено тестом. Время включает подготовку самой модели. Это лимиты solver и структуры задачи, **не OS-квота RAM и не абсолютная гарантия wall-clock deadline**: импорт библиотек, SQL-проверки, игровой пересчёт, работа нативного solver и планирование ОС могут добавлять время. Совокупная память нескольких одновременных запросов отдельно не ограничивалась этим изменением.

## Семантика статусов

| Статус | Условие |
| --- | --- |
| `FEASIBLE` | Есть допустимая проверенная сборка. Даже HiGHS status=0 при нулевой цели не означает оптимальность пользовательской цели |
| `UNKNOWN` | Неподдерживаемая модель, лимит, отсутствие solver, ошибка, неверный incumbent либо неполное покрытие профилей |
| `INFEASIBLE` | Все применимые проверенные модели доказали несовместность **своих проверенных подготовленных пулов**, либо имеется тривиальное доказательство недостаточного числа кандидатов |
| `OPTIMAL` | Зарезервирован для доказанной исходной пользовательской цели; текущий ordinary Beam/feasibility fallback этот статус не возвращает |

`optimality_proven=false` всегда для обычного поиска; `global_infeasibility_proven=false`. Для моделей записаны solver status/message, reason, число строк/ненулевых коэффициентов, лимиты, `pool_sha256`, условия, контейнер и броневой профиль. Неполное покрытие не превращается в общий сертификат INFEASIBLE. Scope — проверенные подготовленные пулы, а не весь аукцион или все варианты Auto. Контейнерная подготовка и её прежние сокращения не изменены. Прежний формат статусов **min_budget** сохранён.
