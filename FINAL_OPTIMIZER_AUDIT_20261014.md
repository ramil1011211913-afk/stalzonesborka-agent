# Итоговый аудит оптимизатора — 2026-10-14

## Решение

Lookahead следует сохранить экспериментальным и выключенным по умолчанию. Он подтверждает ценность как вариант повышенного качества поиска, однако повышает потребление памяти и может увеличивать задержку на CPU. Новая пользовательская возможность выбора режима в этом этапе не добавлялась.

Работа выполнена в `experiment/beam-danger-lookahead`, HEAD `371a55c`, без коммитов и переключений ветки. Математические алгоритмы поиска и режимы цели не менялись. Исправлена найденная при аудите ошибка разбора параметров `/api/meta-builds`.

## Методика и границы

Добавлен воспроизводимый инструмент `app/validation_final.py`. SQLite открывается исключительно с `mode=ro&immutable=1`; инициализация рабочей базы при импорте API отключена. Логи API и сохранение собственных артефактов перенаправлены в новый каталог аудита. Старые журналы и неудачные диагностические прогоны сохранены.

Основной снимок: `auction-snapshot-20261013-232503.db`, 3525 строк аукциона. Для сравнения используется также более ранняя резервная база `stalzone-before-armors-20261013-182016.db`, 3430 строк. В старой базе нет таблицы брони; контрольные профили брони читаются отдельно из основного снимка, без изменения старой базы. Это два близких по времени набора лотов, а не репрезентативная выборка разных рынков и бюджетов.

MILP строится заново из подготовленных производственных кандидатов и общей фиксированной целевой функции. Для нескольких вариантов брони решается отдельная модель каждого профиля с теми же масштабами; лучший результат среди профилей эквивалентен дискретному совместному выбору в этой модели. Проверяются бюджет артефактов, min/max, текущая носимость, конфликты физических экземпляров и запрет повторов типов, когда он задан.

MILP-сертификат относится к подготовленному кандидатному набору и линейным характеристикам. Нелинейная защита и активная отрицательная цель заражения проверяются независимым полным перебором малых задач. Для лексикографических MILP-контролей явно задан допуск `1e-4`, выше численного допуска решателя; последовательные решения фиксируют интервалы равенства. Сопоставляется основной лексикографический ранг; минимальная цена при равном ранге дополнительно проверяется на малых задачах, но не сертифицируется этими MILP-контролями.

Бюджет включает только покупку артефактов. Стоимость брони и контейнера и физические аукционные лоты брони не моделируются. Конечный Beam и оптимистическое округление Lookahead по-прежнему не гарантируют глобальный оптимум произвольного запроса.

## Качество на основном снимке

Выполнены 11 сценариев без брони и 11 с альтернативами `3g6p5`/`5lr71`, каждый при Lookahead 0/1. Включены обычные линейные характеристики, многокритериальный баланс, положительное здоровье как отдельное ограничение, лексикографический порядок, минимальная цена, запрет повторов и максимальные ограничения.

| Lookahead | Совпадение с MILP | Подтверждённые модели профилей |
| --- | --- | --- |
| 0 | 18/22 | Все |
| 1 | 22/22 | Все |

Всего 44 контрольных результата и 66 моделей профилей, все решены до сертификата оптимальности модели. Без Lookahead остаются разрывы по движению и пулестойкости, с бронёй и без неё. Остальные проверенные цели совпали. `min_budget` сохранил 1 853 444 при обоих флагах и при сравнении вариантов брони.

В `min_budget` эвристика Danger Lookahead отключена самим движком: этот режим использует отдельную стратегию. Совпадение результатов при двух значениях флага подтверждает сохранность минимизации бюджета, но не является свидетельством пользы Lookahead для этого режима.

Первый независимый полный перебор: 144 проверки — 8 случайных задач × 3 цели × 2 флага × CPU/GPU/Numba. В каждой задаче совместно сравниваются два профиля брони, проверяются конфликтующие альтернативы физического экземпляра, min/max, заражение и нелинейная производная защита. Все проверки прошли. Дополнительный прогон расширяет активную цель заражением и проверяет порядок выдачи движков.

На более ранней базе результат сравнения такой же: 18/22 совпадений без Lookahead и 22/22 с ним; все 66 моделей профилей сертифицированы. Итого по двум базам: 88 результатов сравнения и 132 модели профилей, Lookahead 1 совпал в 44/44 задачах, Lookahead 0 — в 36/44. На ранней базе минимальная цена составляет 1 824 521, что отражает другой набор лотов; на основном снимке сохранены 1 853 444. Нельзя переносить числовой оптимум между снимками.

Дополнительный полный перебор прошёл ещё 144 проверки с положительным весом заражения и отрицательным направлением его оптимизации; проверены также первые результаты и порядок выдачи движков. Это второй набор целевых функций на тех же восьми малых случайных задачах. Эти проверки подтверждают контракт при достаточно широком луче, но не качество узкого луча на произвольных больших задачах.

## Производительность и память

Среда: Windows, Python 3.12, NVIDIA GeForce RTX 4060 Laptop GPU, 8 физических/16 логических CPU, около 15,2 ГиБ системной RAM. Замеры проводятся последовательно, без одновременного запуска других тяжёлых проверок аудита. Фоновая нагрузка рабочего компьютера не исключена.

Основная матрица: 16 сочетаний backend/флага/нагрузки, по 6 измерений после прогрева — 96 запросов. Ограничение исходного набора 256/768/весь пул после фильтрации даёт 219/612/1424 кандидата; ширины Beam 1000/3000/10000. Цель — бег. Отдельно сравниваются отсутствие брони и два профиля брони.

| Backend | Кандидаты / Beam | Броня | Lookahead 0, медиана / p95, с | Lookahead 1, медиана / p95, с |
| --- | --- | --- | --- | --- |
| GPU | 219 / 1000 | Нет | 0,196 / 0,206 | 0,199 / 0,202 |
| GPU | 612 / 3000 | Нет | 0,256 / 0,310 | 0,333 / 0,343 |
| GPU | 1424 / 10000 | Нет | 0,480 / 0,526 | 0,431 / 0,443 |
| GPU | 1424 / 10000 | Два профиля | 1,113 / 1,178 | 0,992 / 1,205 |
| CPU | 219 / 1000 | Нет | 0,241 / 0,257 | 0,204 / 0,248 |
| CPU | 612 / 3000 | Нет | 0,641 / 0,644 | 0,869 / 0,905 |
| CPU | 1424 / 10000 | Нет | 3,397 / 3,634 | 4,089 / 4,302 |
| CPU | 1424 / 10000 | Два профиля | 6,910 / 7,081 | 8,349 / 8,489 |

Сравнение двух профилей с вариантом без брони включает различие характеристик и структуры поиска, поэтому это наблюдаемое замедление запроса, а не изолированная стоимость одного дополнительного профиля. На полном пуле оно около 2,1–2,3 раза. На CPU Lookahead прибавляет около 20–21% к медиане полного поиска; на GPU эффект зависит от размера задачи.

При двух профилях брони пиковый RSS процесса в основной матрице: GPU около 487/488 МиБ, CPU около 1407/1698 МиБ для флагов 0/1. Замеренный пик занятых блоков стандартного пула CuPy: около 916/1107 МиБ. Занятые блоки после каждого запроса возвращаются к нулю, но зарезервированные блоки остаются в кэше.

Память снимается каждые 10 мс. Кратковременные пики могут быть пропущены; это наблюдаемые пики, а не строгие верхние границы. Глобальная VRAM включает контекст CUDA, резерв пула и другие приложения; она записана отдельно и не приписывается целиком временным матрицам оптимизатора. RSS включает весь процесс и его аллокаторы. Медианы и p95 шести измерений не дают надёжной статистики редких хвостовых задержек.

## Надёжность

После основной матрицы выполнены 10 циклов принудительного подтверждённого CUDA OOM с двумя профилями брони и ограничениями. Каждый CPU fallback совпал с обычным CPU-ответом по полной сериализации. Следующий запрос снова успешно использовал GPU и совпал с исходным GPU-ответом. Глобальный backend не оставался переключённым. Посторонний `RuntimeError` распространился вызывающему коду, после чего новый запрос успешно выполнился.

Отдельная длительная серия содержит 80 запросов полного пула с двумя профилями брони: по 20 на сочетание CPU/GPU и флага, 363 секунды в одном процессе. Проверяются полная сериализация, допустимость результатов, RSS после запросов, временные пики, занятая/зарезервированная CUDA-память и число потоков. Все ответы стабильны и допустимы.

| Backend | Lookahead | Медиана / p95, с | Изменение RSS после первого и последнего запроса, МиБ |
| --- | --- | --- | --- |
| GPU | 0 | 0,965 / 1,116 | +17,26 |
| GPU | 1 | 1,012 / 1,182 | +10,42 |
| CPU | 0 | 6,946 / 7,092 | +2,09 |
| CPU | 1 | 8,267 / 8,393 | +0,94 |

Занятые блоки CUDA после всех запросов равны нулю. Резерв пула стабилен внутри каждого режима: около 1235 МиБ без Lookahead и 1873 МиБ с ним. Число потоков не растёт от запроса к запросу. Умеренный рост RSS в GPU-серии не позволяет объявить отсутствие утечек: возможны прогрев и фрагментация аллокаторов, для различения причин нужна существенно более длительная серия и анализ удержанных объектов. На последних десяти запросах рост RSS составил около 4,42/1,55 МиБ на GPU и 2,66/1,91 МиБ на CPU.

Эта последовательная серия не доказывает отсутствие утечек при многочасовой работе или конкурентных запросах. Принудительный OOM проверяет ветку восстановления, а не реальные условия исчерпания VRAM; точки возникновения OOM внутри движка дополнительно покрываются прежними тестами CUDA OOM.

## Интеграция и найденная ошибка

Через FastAPI TestClient, с настоящим оптимизатором и неизменяемым снимком, проверены повторный запрос, смена брони, экспорт и обратное чтение метаданных уровня, метаоптимизация с обходом кэша без брони, допустимые результаты и ошибочные параметры. Отдельная управляемая проверка кэша подтверждает отбрасывание результатов сверх бюджета. HTML маршрута содержит объяснение бюджета артефактов; полноценная браузерная проверка JavaScript и внешнее сохранение в LunarZone не выполнялись.

Найдена независимая ошибка: `/api/meta-builds` при повреждённом JSON `priorities` или `containers` возвращал HTTP 200 и игнорировал переданные параметры. Теперь синтаксис JSON, типы/конечность весов и непустой список ID контейнеров проверяются до оптимизации. Явно переданный пустой параметр не попадает в кэш обычного запроса. Добавлены 16 поведенческих API-тестов; все прошли. Поисковые алгоритмы не изменены.

В снимке все 131 записи брони имеют уровень 15. Запрос уровня 7 возвращает HTTP 422 из-за отсутствия данных, а не подменяет его уровнем 15. Поддержка передачи произвольного имеющегося уровня остаётся покрыта искусственными тестами предыдущего этапа; реальная база не подтверждает доступность остальных уровней.

## Практический вывод

Подтверждена польза Lookahead для качества на подготовленных контрольных задачах, включая дискретный выбор брони. Цена улучшения — дополнительные временные матрицы и возможное замедление CPU. OOM fallback работает, но увеличивает задержку запроса и не устраняет необходимость запаса системной памяти.

Для включения по умолчанию остаются непроверенными конкурентная нагрузка, редкие хвостовые задержки, реальные OOM под нагрузкой и более широкий набор независимых снимков/бюджетов. Текущая рекомендация — оставить экспериментальный флаг выключенным и рассматривать включение как осознанный выбор повышенного качества для подходящих ресурсов. Значение флага по умолчанию не изменено.
