# Сравнительный аудит объединённого экспериментального поиска

**Всю конфигурацию продвигать автоматически нельзя: критерий «без ухудшений полного ранга» не выполнен.** Обнаружена регрессия Balanced Constraint Lookahead в сценарии движения при беге ≥10% и здоровье ≥0, без брони и с выбором брони. Chunking эту регрессию не вызывает. Возвращённые сборки допустимы; проблема относится к качеству отбора состояний конечного Beam.

В остальных проверенных задачах объединение сохранило или улучшило полный ранг. Оно заметно уменьшает временную память balanced/lexicographic, но может замедлять CPU. Joint Tail + Frontier сохраняет пользу для min-budget и также требует осознанного выбора затрат.

Контрольный HEAD `c785e231b91b28dd0214cc1b72cf2debbbfcdbe3`, ветка `experiment/beam-danger-lookahead`. Staging, коммиты, переключение ветки и изменение обычного поиска не выполнялись. Lookahead по умолчанию остаётся выключенным. Данные этапа: `data/validation/combined-audit-20261015-014616/`.

## Что реализовано

Добавлен отдельный адаптер `app/_combined_search.py` и 23 теста `tests/test_combined_search.py`. Существующие runtime-модули и эвристики не изменялись.

`build_combined_sets()` делает одну попытку на подготовленный пул контейнера/брони. Общий Objective передаётся без замены и пересчёта масштабов. Нет портфеля, повторного полного поиска, объединения результатов разных стратегий или автоматического включения режима в API/UI.

| Режим | Настройки адаптера |
| --- | --- |
| balanced | Quality 2000 с Danger Lookahead, chunked scoring, Constraint Lookahead |
| lexicographic | Quality 2000 с Danger Lookahead, chunked scoring; Constraint Lookahead выключен |
| min_budget | Штатное блочное расширение min-budget, Joint Tail, Suffix Frontier; Danger/Constraint Lookahead выключены |

Важное уточнение: min-budget уже использует собственное блочное расширение. Параметр `expansion_chunk_size` влияет на отдельный путь оценки balanced/lexicographic и не добавляет ещё одну оптимизацию min-budget. В адаптер он передаётся единообразно, но независимый эффект chunked scoring для min-budget не заявляется.

Price Scan явно выключен. Лимит представителей по умолчанию сохранён — 256. Для сравнительного аудита явно выбран 2048, чтобы точный хвост действительно применялся к реальному набору с 1195 представителями. Это не изменение пользовательского значения по умолчанию.

```python
from app._combined_search import build_combined_sets

# Только исследовательский вызов; для balanced известен контрпример качества.
builds = build_combined_sets(
    budget,
    beam_width=2000,
    expansion_chunk_size=262144,
    joint_tail_limit=2048,
    **request,
)
```

## Контроли и методика

Обычный поиск на реальных запросах запускался через штатный `build_artifact_sets()`, с Lookahead=0. В измерениях по одинаковым подготовленным пулам его контроль использует Beam Width=10000 для balanced/lexicographic и 20000 для min-budget, без дополнительных механизмов. Это контроль первой Beam-попытки, а не измерение загрузки SQLite, HTTP или всех возможных маршрутов Numba/retry.

Прежний Quality 2000 определён явно: ширина 2000, Danger Lookahead включён, без chunking, Constraint Lookahead и Joint Tail. Это соответствует `build_quality_sets(..., constraint_lookahead=False, expansion_chunk_size=None)`; нынешние значения по умолчанию самого старого экспериментального wrapper здесь не используются как определение контроля.

Объединённый режим использует политику таблицы выше. Сравнивается полный `Objective.sort_key`: balanced F и стоимость; lexicographic квантизованные приоритеты и стоимость; min-budget стоимость. Дешевизна не оправдывает ухудшение основной цели balanced/lexicographic.

MILP пересчитывался по текущим подготовленным моделям. Для balanced/lexicographic он сертифицирует основную цель, но не отдельную минимизацию цены среди всех равных основных целей. Полный ранг, включая цену, отдельно сравнивается между стратегиями. Сертификаты относятся к подготовленным кандидатам и не доказывают глобальный оптимум произвольного аукциона.

Все ограничения соблюдаются, но более дешёвая правая сборка проигрывает по основной цели. Обычный поиск в этих запросах совпал с Quality. MILP подтвердил основную цель Quality/только chunking: для запроса без брони и обоих подготовленных моделей с бронёй получены сертификаты.

Аblation выполнена отдельно на CPU и GPU:

- Quality 2000 = chunking без Constraint Lookahead, включая полный ранг.
- Constraint Lookahead без chunking = объединённый режим.
- Последние два варианта хуже первых двух в обоих запросах.

Это локализует источник в изменённой оценке неполных сборок Balanced Constraint Lookahead, а не в chunking, совместном выборе брони, min-budget или передаче параметров адаптера. Точный уровень потери префикса в этом аудите не трассировался. Новые эвристики, исключения по именам характеристик или скрытый второй поиск для маскировки результата не добавлялись.

Сценарий `min_constraints` ранее не входил в основную таблицу из 22 MILP-контролей. Добавление его в расширенную проверку изменило итоговый вывод. Вновь найденный контрпример воспроизводится в `ablation.py` и `ablation_cpu.py`; результаты и сертификаты — `ablation.json`, `ablation-cpu.json`.

Новые модели используют шесть независимых случайных пулов по 64 кандидата, физические альтернативы, два профиля бонусов брони, ограничения бюджета/характеристик и все три режима; дополнительно включён известный контрпример позднего восстановления здоровья. Seed отличается от предыдущих этапов. Это независимые подготовленные задачи, а не новые независимые снимки реального аукциона.

Независимый oracle использует ещё шесть новых seed, по 16 кандидатов, k=4, запрет/разрешение повторов, физические альтернативы, два профиля брони и все режимы. Для каждой задачи перебираются все 1820 сочетаний; игровые преобразования, ограничения и целевые оценки записаны явно. Для каждой из трёх стратегий на CPU/GPU проверены всё множество допустимых возвращённых комбинаций, оценки и полный лучший ранг. Меток Lookahead 0/1 здесь нет: у каждой стратегии собственная явно заданная политика флага. Это исключает повторение прежней ошибки диагностического драйвера.

## Решение

Chunked scoring остаётся убедительным отдельным кандидатом на дальнейшую проверку: уменьшает временные матрицы и в выполненных сравнениях сохраняет ранжирование Quality. Lexicographic использует только его поверх Quality. Joint Tail + Suffix Frontier сохраняется явным экспериментом min-budget, с действующим лимитом и без автоматического повышения до 2048.

Balanced Constraint Lookahead нельзя считать монотонным повышением качества и включать автоматически по одному наличию min/max. Следующий адресный вопрос — потеря префикса MILP-оптимальной сборки в найденном `min_constraints`, а не расширение портфеля или ещё одна эвристика. Этот аудит оставляет компонент и объединённую конфигурацию исследовательскими.

Сохранность исходных файлов, прежних данных, резервных копий и Git-индекса фиксируется SHA-256 в `before.json`, `sources.json` и итоговом `final-state.json`. Существовавшие runtime-файлы, алгоритмы и контрольные данные в этом этапе не переписывались. Новые изменения — только отдельный адаптер, тесты, этот отчёт и новый каталог аудита.

Итог: SHA-256 всех 11764 защищённых существовавших файлов совпали, пропаж нет. Все 15 наложенных исходников/тестов совпадают с изолированной проверенной копией. Git-индекс побайтно сохранён, staged-файлов 0; `git diff --check` прошёл. HEAD и ветка прежние. В `final-state.json` прямо записано `audit_criterion_passed=false` и сохранены обе регрессии полного ранга.
