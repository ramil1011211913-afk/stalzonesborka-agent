## Причина предполагаемого противоречия

`min_thresholds["cost"]=3` — действительное ограничение игровой характеристики **«Заряда за активацию»**, а не цены покупки. Оно означает итоговое значение не менее 3. В каталоге эта характеристика присутствует у «Многогранника» (`ljpq`); `/api/all-stats` возвращает её название, UI создаёт обычные поля мин/макс, API передаёт значение без переименования. В MILP это сумма соответствующих текущих характеристик с учётом бонусов; финальная игровая проверка использует ту же характеристику. Это не игнорируемое поле и не автоматическое ограничение стоимости. Бюджет проверяется отдельно. Само наличие поля в запросе не позволяет установить намерение пользователя.

## Пулы, физические экземпляры и кэш

На неизменяемой копии все выбранные аукционные ID доступны с прежними ценами; собственные экземпляры однозначно совпадают. Все семь вариантов свидетеля присутствуют в целевых подготовленных пулах. Исходный пул и последующие `min_budget`-пулы содержат **2321** кандидата; точный ключ совпадает. В изолированном процессе после помещения свидетеля оба механизма — exact-pool и physical remap — находят его. Затем полная текущая проверка правильно отклоняет его по `cost>=3`; это **отказ валидации, а не cache miss**. При снятии этого условия текущий builder возвращает прежнюю сборку при беге ≥16,8 и ≥16,7, сохраняя исходный solver `time_limit` и `optimality_proven=false`.
