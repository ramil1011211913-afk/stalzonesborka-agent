# AUCTION REFRESH RACE FIX GATE — 18.10.2026

## Решение: GO, 15/15

Исправление проверено в изолированных копиях и перенесено в рабочее дерево. Сервер не запускался и не перезапускался; развёртывание и commit не выполнялись. GO означает готовность к рассмотрению и не гарантирует доступность исторических игровых предложений сейчас.

## Первопричина

Коллектор атомарно заменяет группу item/region через DELETE + INSERT. Новые локальные SQLite ID не обязаны совпадать со старыми даже для того же игрового предложения. Solver успешно решает уже подготовленную модель, но исходные строки могут исчезнуть к повторной проверке. В диагностике оба состава B были корректны на неизменном точном пуле; при публикации Вихрей проверка находила 5/7 строк. Отказ воспроизводился также без conservative.

Полная трассировка исходного исторического отказа отсутствовала; этот предел прежнего аудита не отменяется. Исправляется доказанно воспроизводимая гонка, а не предполагаемая ошибка физики B.

## Изменённые рабочие файлы

- `app/_quality_market.py` — новый commit-aware наблюдатель, без запуска refresh и записи state.
- `app/_max_quality.py` — один ограниченный повтор, разделённые причины, история попыток, понятное сообщение UNKNOWN и суммарные времена.
- `tests/test_quality_market.py` — 38 новых параметризованных проверок SQLite commit, подготовки, retry, дескрипторов и статусов.

UI/API код не менялся: существующий интерфейс отображает `search_status.message`. Текст при смене рынка: **«Аукцион обновился во время поиска. Повторите запрос»**. При недоступном контроле согласованности — отдельное сообщение об этой невозможности.

## Архитектура согласования

Один autocommit SQLite observer остаётся открытым от начала подготовки до заключительной проверки. `PRAGMA data_version` сравнивается только на этом же соединении: любой commit другой связи обнаруживается, включая публикацию группы внутри неизменной refresh generation. Отдельно read-only читается уже существующая строка `auction:EU` из app-state: generation и running. Сам observer не держит длительную read-транзакцию и не блокирует писателя на всё время solver.

Это **оптимистическая проверка согласованности**, а не заявление о создании физического snapshot-файла. Если между первым и последним чтением изменился commit counter, все прочитанные профили/решения попытки отбрасываются. Неизменность counter и отсутствие активного refresh подтверждают согласованность использованного состояния для принятой попытки. Публикация во время подготовки также обнаруживается; смешанный пул не получает сертификат.

Если refresh ещё активен до начала расчёта, немедленно возвращается UNKNOWN без solver. Если он начался/продолжился после начала попытки — её результат отбрасывается. Повтор разрешён только при доступной существующей refresh-записи с running=false и остатке ≥1 с. Отсутствующая state-база не создаётся: стабильная попытка защищена commit counter, но после изменения без сведений о завершении refresh повтор запрещён. При ошибке чтения согласованность не имитируется.

Вторая попытка заново выполняет штатную подготовку и строит новую модель. Не переносятся старые индексы, ID или сертификаты. Повтор не вызывает main endpoint, коллектор или обновление аукциона. Единственный quality-slot удерживается на обе попытки; deadline исходный, лимиты модели/памяти/узлов прежние. Третий запуск запрещён. При нехватке времени, активном refresh или новой смене данных — UNKNOWN без сборок.

Commit counter относится ко всей рыночной DB, а не только выбранному региону: изменение другой таблицы может консервативно вызвать лишний повтор. Гарантия относится к последней проверке; изменения после неё и весь живой EU-аукцион не сертифицируются. Полной блокировки рынка до отправки HTTP-ответа нет.

## Статусы и строгая валидация

В каждом модельном результате сохранён исходный worker `reason`, stages, returncode, bounds и сообщения; добавлены `worker_reason`, `validation_reason`, `validation_details`. Различаются неверные индексы solver, физический отказ и игровой отказ. Верхний `search_status` включает причины, `attempts` и `retry_count`; математический `finished` больше не скрывает установленный отказ последующей проверки.

Непринятый рыночный результат не выдаётся как FEASIBLE/OPTIMAL. Каждая возвращённая сборка проходит текущую строгую проверку исходных физических дескрипторов, `_process_combo()` и `_final_valid()`. В B проверяется оригинальный `_quality_source`, сценарный minimum view не подменяет процент реального лота. Цены, регион, срок, качество, заточка, бонусы, исходные проценты и stats_random проверяются существующим кодом без ослаблений. Не производится сопоставление по одному названию или цене; локальный ID не объявляется внешним ID аукциона.
