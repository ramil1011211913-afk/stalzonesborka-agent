# Физическая доступность артефактов — 14.10.2026

Ветка `experiment/beam-danger-lookahead`, HEAD `371a55c` сохранены. Коммиты, переключения веток, удаления и изменения существующих контрольных данных не выполнялись. Lookahead по умолчанию остаётся выключенным.

## Диагноз

`auction_lots` уже содержит уникальный первичный ключ `id`, но загрузчик не переносил его в `ArtifactOption`. Несколько предполагаемых наборов бонусов одной строки становились независимыми кандидатами. При `allow_duplicates=True` ограничения в Beam и Numba на такие кандидаты отсутствовали; Python-перебор и MILP также не связывали альтернативы одного предложения.

## Реализация

Добавлен `app/_physical_items.py` с едиными правилами идентичности и доступности.

`ArtifactOption` теперь сохраняет:

- `auction_lot_id` — исходный `auction_lots.id`, отдельно от типа артефакта;
- `owned_instance_id` — идентификатор принадлежащего пользователю экземпляра;
- `physical_id` — обозначение экземпляра для передачи результата и диагностики.

Все альтернативы одной аукционной строки получают одинаковый ID. ID сохраняется при пересчёте характеристик под контейнер и выводится в JSON сборки. Исходный `auction_lot_id` имеет приоритет над производным обозначением, поэтому смена `physical_id` не позволяет повторно использовать известный лот.

Собственный экземпляр может передаваться с `instance_id` либо `owned_instance_id`. Если ID не передан или равен `null`, назначается отдельная идентичность по позиции в текущем списке. Автоматические и явно заданные идентичности имеют разные пространства имён. Две одинаковые записи без ID считаются двумя экземплярами; две записи с одним явно заданным ID — альтернативами одного экземпляра. Для идентичности между запросами следует передавать явный ID.

Правило готовой комбинации:

1. Один физический лот/экземпляр выбирается не более одного раза.
2. При `allow_duplicates=False` дополнительно запрещается повторение `item_id`.
3. При разрешённых повторах два независимых предложения или собственных экземпляра одного типа допустимы.

Для движков достаточно одного массива групп конфликтов: при разрешённых повторах это физические экземпляры, при запрещённых — типы. Предварительно проверяется, что один физический объект не представлен разными типами. Уникальность типа тогда включает уникальность физического объекта. Проверки отключаются только если все группы кандидатов уже уникальны.

Правило подключено к обычному Beam, блочному расширению `min_budget`, четырём ядрам Numba для 4–7 слотов, малому Python-перебору, Python fallback и `_process_combo`. MILP получает ограничения `sum(x[group]) <= 1` для физических альтернатив и, при необходимости, типов. Обновлены оба валидатора: `validation_exact.py` и отдельный `exact_validator.py`.

Подготовка кандидатов теперь ограничивает число физических предложений, а не число их гипотез. Отбор компенсаторов сохраняет независимые одинаковые экземпляры при наличии места в резерве. Базовое разнообразие компенсаторов имеет приоритет перед заполнением резерва копиями. Первое расширение резерва ухудшало остановку до 59,461059; после исправления порядка отбора восстановлено 66,502794. Промежуточные результаты сохранены для диагностики.

Старый кэш мета-сборок не считается доказательством физической доступности. Введены отдельный путь `meta_builds_balanced_physical_v1.json`, версия 3 и маркер `availability_contract="physical-v1"`. Старые файлы не удалялись и не перезаписывались; предварительное вычисление кэша не запускалось.

## Область гарантии

В поиске по текущей базе альтернативы одной строки аукциона больше не могут попасть в одну сборку. Собственные экземпляры учитываются отдельно от предложений аукциона и от типа артефакта.

`auction_lot_id` является ID строки локальной базы, а не долговечным внешним идентификатором: коллектор удаляет и заново вставляет предложения при обновлении. Идентичность гарантирована в рамках текущего снимка/запроса. Уникальность реальных предложений между разными строками источника, актуальность продажи после расчёта и достоверность предполагаемых бонусов не сертифицированы этим этапом. Один лот моделируется как ресурс вместимости один; отдельная модель покупки пачек по `amount` не вводилась.

Для старых программных кандидатов без исходного ID сохранена совместимость: разные объекты считаются отдельными экземплярами, повторное использование того же объекта запрещено. Производственный загрузчик аукциона всегда задаёт исходный ID.

Глобальный оптимум по-прежнему не гарантирован. MILP-сертификаты относятся к подготовленному набору кандидатов и выбранным линейным целям. CUDA OOM и повторная проверка ограничений после добавления брони остаются следующими этапами.
