# Min-budget: большие наборы и совместная оценка последнего слота

Работа продолжена от реального состояния проекта: ветка `experiment/beam-danger-lookahead`, HEAD `c785e231b91b28dd0214cc1b72cf2debbbfcdbe3`. Предыдущие эксперименты сохранены. Staging, коммиты и переключения веток не выполнялись. Обычный поиск и `STALZONE_DANGER_LOOKAHEAD=0` по умолчанию сохранены.

Практический результат: существующий Joint Tail применим к контрольному набору из 1577 кандидатов при явном `joint_tail_limit=2048`, без увеличения Beam Width и без повторного полного поиска. Ограничение временных матриц остаётся действующим. Цена этого режима заметна, особенно на CPU; улучшения качества на данном снимке нет, поскольку обычный поиск уже находит MILP-оптимум.

Новый обход продолжений по цене корректен в проверенных задачах, но оказался слишком медленным. Более перспективен исследовательский отбор по совместному отношению цены, индекса и доступности: он сократил 1566 представителей до 1195. Этот отбор пока НЕ подключён к runtime.

Артефакты этапа: `data/validation/joint-index-20261014-235019/`. Имя каталога отражает начало работы 14 октября; этап завершён 15 октября.

## Почему точное сжатие почти не работает

Повторно подготовлен реальный min-budget запрос с ограничением бега не ниже 10%, на неизменяемой копии снимка аукциона.

| Свойство подготовленного набора | Количество |
| --- | ---: |
| Кандидаты | 1577 |
| Различные векторы raw-характеристик | 438 |
| Различные цены | 622 |
| Профили raw + цена + признак компенсатора | 1270 |
| Профили с единственным вариантом | 1057 |
| Различные конфликтные группы | 1577 |
| Представители прежнего Joint Tail | 1566 |

В матрице этого запроса пять заражений и `sprint_speed_modifier`. Различных значений бега — 260; отдельных заражений — от 5 до 84. Большая часть слабого сжатия объясняется ценами и необходимостью сохранять доступные независимые экземпляры, а не лишними колонками матрицы. Подробности: `compression.json`, воспроизведение: `compression.py`.

Удаление дорогих копий только по сходству характеристик небезопасно. Более дешёвый вариант может находиться до последнего индекса префикса либо принадлежать уже занятому физическому лоту. Исключение из последнего слота также нельзя переносить на весь кандидатный набор: предыдущим слотам могут требоваться эти экземпляры.

## Проверенные варианты

### Существующий Joint Tail с большим явным лимитом

Дополнительный runtime-код для этого не требуется:

```python
from app._min_budget_joint import build_joint_budget_sets

builds = build_joint_budget_sets(
    budget,
    beam_width=2000,
    joint_tail_limit=2048,
    **request,
)
```

Это отдельный экспериментальный вызов для `min_budget`. Лимит представителей по умолчанию остался 256. Значение 1024 на контрольном снимке всё ещё отключает уточнение; 2048 допускает все 1566 представителей. Прежний `rank_last_slot` разбивает вычисления на блоки не более 262144 пар для этих размеров набора. Кандидаты сверх лимита не обрезаются: уточнение целиком пропускается.

### Обход продолжений по цене

Добавлены `app/_min_budget_stream.py` и `tests/test_min_budget_stream.py`; в `app/_beam_search.py` добавлен выключенный по умолчанию флаг `joint_budget_scan` и передача его параметров через полный CPU-повтор после CUDA OOM.

Отдельная точка входа — `build_stream_budget_sets()`. Она не подключена к обычному builder, API, UI или портфелю. Параметры: `joint_scan_block=32`, `joint_scan_max_pairs=32768`. Числа должны быть положительными целыми; логические значения отклоняются. При явном одновременном выборе scan и прежнего tail используется scan; их оценки не складываются. В balanced/lexicographic флаг не действует.

Все кандидаты упорядочиваются по цене. Для каждого префикса проверяются порядок индексов, бюджет, число компенсаторов и физические/типовые конфликты. Только доступные пары передаются штатной итоговой оценке с бронёй, игровыми преобразованиями, min/max и носимостью. После первого ценового блока с допустимым продолжением префикс больше не проверяется; внутри блока выбирается самая низкая действительная стоимость.

Это точная оценка одного оставшегося слота среди подготовленных кандидатов. Ограничение числа пар относится к временным блокам, а не к общей RAM/VRAM и не ко времени поиска. В худшем случае проверяются все пары. Ранее отброшенные уровни Beam не восстанавливаются, гарантии глобального оптимума нет.

Гипотеза об ускорении не подтвердилась: уменьшение числа дорогих итоговых пересчётов не компенсировало большое количество мелких GPU-операций и синхронизаций. Прототип сохранён как явно экспериментальный, к использованию по умолчанию не рекомендуется.

### Исследовательский отбор по цене и суффиксу

Реализация только в `frontier_research.py`, без изменения рабочих правил подготовки кандидатов.

Для кандидата последнего слота рассматриваются только варианты с точно такими же raw-характеристиками и признаком компенсатора, с большим индексом и не большей ценой. Его можно исключить из продолжений, если существует подходящая замена той же конфликтной группы либо такие замены существуют в как минимум `k` разных группах. Префикс занимает не более `k-1` групп, поэтому хотя бы одна замена доступна. Замена с большим индексом сохраняет порядок продолжения. Броня, преобразования и ограничения одинаковы для вариантов одного профиля.

Правило применяется только к последнему слоту. Все исходные кандидаты остаются доступными для предыдущих слотов. Более поздние замены могут, в свою очередь, иметь ещё более поздние и не более дорогие замены; цепь конечна, поскольку индекс строго возрастает.

На реальном наборе осталось 1195 представителей, примерно на 24% меньше прежних 1566. Это всё ещё выше 1024. В 12 случайных наборах по 333 кандидата проверены 1524 префикса: лучшая цена совпала с проверкой всех продолжений. В изолированных процессах дополнительно выполнена подстановка этого отбора в существующий Joint Tail; MILP для контрольного запроса без брони и двух профилей брони совпал. Подстановка существует только в инструментах аудита; глобальные функции рабочего приложения не менялись.

## Проверки корректности

Полная регрессия запускалась из отдельной копии исходников, с собственными SQLite-фикстурами. Audit hook запрещал открытие исходных проектных SQLite-файлов. Все четыре журнала подтверждают отсутствие таких обращений.

| Режим | Результат |
| --- | --- |
| GPU, Lookahead 0 | 423 passed |
| GPU, Lookahead 1 | 423 passed |
| CPU Python 3.15, Lookahead 0 | 333 passed, 90 skipped |
| CPU Python 3.15, Lookahead 1 | 333 passed, 90 skipped |

Новые 32 теста проверяют сравнение с полным набором продолжений, ограничения размеров временных блоков, независимость физических лотов, бюджет, компенсаторы, нулевую цену, min/max, броню, нелинейную защиту, CPU/GPU, стоимость 20 в контрпримере и сохранение параметров при искусственном CUDA OOM. Поведение других режимов при новом флаге проверено отдельно. Предупреждение GPU-прогонов — прежнее Starlette/httpx deprecation.

Дополнительные проверки:

- 22/22 сценария снимка совпали с MILP; ни один полный ранг не ухудшился относительно Quality 2000.
- В подготовленных задачах min-budget — 13/13 совпадений с MILP. Общий результат всех трёх режимов — 38/39; неизменившийся balanced-контрпример поздней компенсации здоровья не исправляется этим экспериментом. Все 39 результатов не хуже исходного Quality 2000.
- Независимый малый перебор: 144 проверки режима/backend/Lookahead, по два профиля брони в каждой — 288 сравнений профилей. Все прошли.
- Дополнительные большие задачи: шесть моделей по 300 кандидатов, два профиля бонусов, физические альтернативы и запрет/разрешение повторов. Для каждой модели независимо перебраны все 44850 пар и решена MILP; CPU и GPU при Beam Width=1 совпали, 12/12 backend-проверок. Более жёсткое ограничение здоровья дало оптимальные стоимости 0, 3, 1, 22, 3, 10. Отдельные шесть более мягких моделей также прошли и проверили допустимые нулевые стоимости.
- Существующий Joint Tail при лимите 2048 и исследовательский отбор отдельно совпали с MILP трёх подготовленных моделей реального запроса: без брони и с двумя профилями брони. Минимальная стоимость в обоих случаях — 1 853 444.

Узкая ширина 1 в больших парных задачах проверяет точность оценки последнего слота: при двух слотах она доступна уже до первого сужения. Это не доказательство точности узкого Beam для произвольного числа слотов.

## Измерения

Подготовленные модели, Beam Width=2000, один прогрев и три последовательных измерения, без параллельной нагрузки тестов. Это предварительные медианы на одной машине и одном снимке. Вычисленный в JSON p95 по трём измерениям не является надёжной оценкой хвостовых задержек. Память опрашивалась каждые 10 мс; краткие пики могут быть пропущены.

Во всех строках стоимость 1 853 444. Повышение лимита практически применимо на этом GPU, но не бесплатно. Дополнительная работа на этом снимке не улучшает уже оптимальный результат.

Обход по цене: на контрпримере GPU-медиана составила 8,786 с при лимите 8192 пар, 2,462 с при 32768 и 0,603 с при блоке 128/лимите 131072. Во всех случаях стоимость 20; прежний Joint Tail решает этот контрпример примерно за 0,046 с. На реальном наборе scan/8192 дал 17,508 с, 33 МиБ CuPy used, стоимость 1 853 444. После этого серия остановлена по неприемлемой задержке; оставшиеся конфигурации реального набора и CPU-замеры scan не завершены. Частичные результаты сохранены, завершённая полная серия не заявляется.

Парный замер исследовательского сокращения, отдельный процесс:

В обеих конфигурациях лимит 2048, стоимость одинакова. RSS около 516 МиБ на CPU в обоих вариантах; на GPU CuPy used 59 → 62 МиБ. Снижение пика памяти не подтверждено. Разница CPU-времени с предыдущей серией показывает вариативность замеров; универсальное ускорение не заявляется.

## Сохранность и решение

Проверены SHA-256 всех 11475 существовавших защищённых файлов, включая прежние данные, контрольные результаты и резервные копии: изменений и пропаж нет. Единственный существовавший файл, разрешённый к изменению в этом этапе, — `app/_beam_search.py`; точная разница с предыдущим этапом сохранена в `beam-change.diff`. SHA-256 12 наложенных исходников/тестов совпадают с изолированной проверенной копией. Git-индекс побайтно не изменился; staged-файлов 0. `git diff --check` прошёл. HEAD и ветка сохранены. Итоговые проверки — `final-state.json`.

Рабочие изменения этапа: расширение экспериментальных параметров Beam, новый модуль обхода по цене и 32 теста. Исследовательское сокращение и инструменты измерения находятся только в новом каталоге валидации. Старые эксперименты, данные, backups и настройки по умолчанию не изменялись.

Рекомендация: для явно выбранного эксперимента на проверенном GPU допустим существующий Joint Tail с лимитом 2048; для CPU учитывать примерно четырёхкратное замедление данного запроса. Обход по цене не продвигать. Следующая обоснованная реализация — отдельное подключение и расширенная проверка отбора по цене и суффиксу, с сохранением всех кандидатов для предыдущих слотов и действующих ограничений памяти. Автоматически объединять эксперименты или включать Lookahead по умолчанию оснований нет.
