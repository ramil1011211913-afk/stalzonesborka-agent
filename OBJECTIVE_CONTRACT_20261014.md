# Единая целевая функция оптимизатора — 14.10.2026

Работа выполнена в `experiment/beam-danger-lookahead`, HEAD `371a55c`. Коммиты и переключения веток не выполнялись. Значение по умолчанию для `STALZONE_DANGER_LOOKAHEAD` осталось `0`.

## Реализованный контракт

`app/_objective.py` содержит неизменяемый `Objective` с тремя режимами:

- `balanced` — основной режим: `F = sum(w_i * d_i * final_stat_i / S_i)` по всем положительным весам. Для пяти видов накопления заражения направление отрицательное, для остальных характеристик положительное.
- `lexicographic` — сравнение направленных итоговых характеристик в явно заданном `priority_order`. Порядок должен содержать каждую характеристику с положительным весом ровно один раз; величины весов внутри этого режима не задают порядок.
- `min_budget` — минимальная стоимость при выполнении ограничений. Скалярная оценка равна отрицательной цене; положительный бюджет ограничивает стоимость, нулевой снимает этот предел. Совместимость с прежним `min_budget=True` сохранена.

При равной цели предпочтение отдаётся меньшей стоимости. В лексикографическом режиме скалярные `total_score` и `priority_value` показывают диагностическую взвешенную сумму; сортировка использует лексикографический кортеж, а не этот скаляр.

Числовое равенство для лексикографического порядка определяется фиксированными интервалами: `floor(d_i * s_i / tolerance + 0.5)`, стандартный `tolerance=1e-6` в единицах исходной характеристики. Это транзитивное правило. Значения по разные стороны границы интервала могут различаться даже при расстоянии меньше допуска; правило не тождественно попарному `abs(a-b) <= tolerance`.

## Фиксированное нормирование

Масштабы вычисляются один раз после загрузки аукционных и собственных вариантов, до поиска и сокращения кандидатов. Для каждой выбранной ёмкости используются характеристики артефактов с её эффективностью:

`S_i = max(1, max_over_selected_containers(slots * max_abs_artifact_stat_i + abs(container_bonus_i)))`.

Для остановки предварительно рассчитывается производная характеристика отдельного артефакта. Эта формула задаёт масштаб величины, а не точную границу достижимого значения нелинейной готовой сборки. Масштаб не пересчитывается на уровнях Beam и не зависит от его ширины. Все выбранные ёмкости получают один объект `Objective`. API позволяет явно задать положительные фиксированные масштабы через `objective_scales`; некорректные параметры отклоняются до начала поиска.

Нулевые и отрицательные веса не участвуют в цели. Они также исключаются из подготовки запроса, чтобы нулевой вес не менял выбор контейнеров, кандидатов или включение эвристики частичного заражения.

## Интеграция и связанные исправления

- Beam оценивает завершённые комбинации той же функцией, что `builder.py`. Штрафы достижимости остаются только эвристикой неполных комбинаций. Завершённые комбинации проверяются по ограничениям до сокращения луча.
- Numba рассчитывает защиту от положительного заражения перед бонусами контейнера, затем производную остановку. Проверяет минимум, максимум и носимость на итоговых значениях. Все четыре ядра для 4–7 слотов используют новые коэффициенты и лексикографические ранги. Удалены неиспользуемые матрицы старой оценки и EHP. Скалярная сумма не требует SciPy/BLAS; стоимость не округляется до целого внутри движка.
- Финальная сортировка, промежуточное сокращение пула и разнообразие используют общий порядок. Pareto учитывает направления и коэффициенты, а для лексикографического режима — интервалы равенства. Лучший вариант по цели закрепляется первым до отбора разнообразия.
- Требование носимости стало жёстким также для небольших перебираемых пулов: возвращение неносимых вариантов как запасного результата устранено.
- Браузер сохраняет серверный порядок. Удалена повторная сортировка по скалярной оценке, нарушавшая `lexicographic`.
- `meta_optimizer` ищет выбранные ёмкости одним запросом с общими масштабами. Новый кэш имеет версию контракта и отдельное имя; прежний файл кэша сохранён и не используется как результат нового контракта.
- После добавления брони обновляются итоговая оценка и порядок; устранён повторный учёт уже преобразованной остановки.

Основной режим обычного запроса теперь `balanced`. Отдельные режимы доступны через Python и HTTP API; отдельный переключатель лексикографического режима в интерфейсе не добавлялся. HTTP-параметры `priority_order` и `objective_scales` передаются как JSON.

Пример Python:

```python
build_artifact_sets(
    budget=12_000_000,
    priorities={"sprint_speed_modifier": 10, "health_bonus": 8},
    optimization_mode="lexicographic",
    priority_order=["sprint_speed_modifier", "health_bonus"],
)
```

Для сбалансированной оценки достаточно опустить `optimization_mode` и `priority_order`. Ограничение `min_thresholds={"health_bonus": 0}` остаётся самостоятельным: баланс не гарантирует положительное здоровье.

## Проверки

Полный набор на Python 3.12 / CUDA: **145 пройденных тестов** при флаге Lookahead `0` и `1`. На Python 3.15 / CPU: **129 пройденных, 16 пропущенных** — 15 требуют CUDA, один требует отсутствующего в этом окружении FastAPI. После последней корректировки Pareto повторно прошли полный набор GPU и 10 интеграционных проверок CPU; API-проверка CPU пропущена по той же причине. Два предупреждения GPU относятся к сторонним библиотекам TestClient/AnyIO.

Новые проверки покрывают фиксированные и нулевые масштабы, влияние веса здоровья, скалярную и векторную оценки, явный лексикографический порядок и равенства, ценовые равенства, неизменность масштабов при смене ширины луча, единый объект для контейнеров, жёсткую носимость, защиту/бонусы/остановку, ограничения максимумов, API, кэш и броню. На маленьких задачах Beam и Numba сопоставлены с независимым полным перебором: три режима, разрешённые/запрещённые повторения, CPU/CUDA и шесть наборов данных на сочетание.

Восемь прежних MILP-моделей пересобраны с новыми коэффициентами и масштабами; добавлена девятая модель для бега и здоровья. Все девять MILP завершились со статусом оптимальности и нулевым разрывом. ## Пределы доказательства и оставшиеся задачи

Конечный Beam и оптимистический Lookahead с округлением бюджета не гарантируют глобального оптимума. MILP-сертификаты относятся к подготовленному набору кандидатов контрольного снимка и к линейным целям этих девяти моделей. Нелинейная остановка и лексикографическая цель здесь проверены перебором небольших задач и регрессией, а не глобальным MILP-сертификатом.

Учёт физических лотов остаётся нерешённым: альтернативы одного аукционного предложения могут представляться разными кандидатами. Нельзя трактовать оптимум этой модели как сертификат реально покупаемой сборки на всём аукционе. CUDA OOM с гарантированным повтором поиска на CPU также остаётся отдельной задачей.

Броня по-прежнему добавляется после поиска. Оценка возвращаемых характеристик согласована, но поиск не оптимизирует её совместно с артефактами; повторная проверка всех пользовательских ограничений после добавления брони требует отдельного изменения.
